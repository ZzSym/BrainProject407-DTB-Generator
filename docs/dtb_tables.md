# 从脑区矩阵理解 DTB 连接表

本页介绍 BrainProject407 既有 DTB 生成流程。公开仓库不包含研究矩阵、连接表、逐人输出清单或外部 DTB 生成器。实际运行需要从授权渠道取得输入数据、节点 metadata 和匹配的外部代码环境。

这里的处理参数来自 **2026-10-10 检查快照**。该快照有588个 Shen268 矩阵，其中8人另有 DTB 连接表。2026-10-11 仅整理公开教程，没有重新检查实时生成进度。

## 脑区边表与神经元连接表

Shen268 矩阵的每个行列下标表示一个脑区。对角值是 T1w 灰质概率求和的权重代理，非对角值是 DWI 流线计数。将非对角非零元素展开为 `source_node,target_node,weight`，得到的是脑区层面的边表，保留的仍是脑区结构权重。

DTB 连接表的连接端点则是具体模型神经元。生成它需要确定神经元规模、每个脑区的兴奋/抑制群体、神经元分配、连接采样规则、通道参数和随机种子。脑区流线计数不能直接当作神经元突触数；灰质代理也不是测得的神经元数量。

本仓库的脑区边表工具不会执行神经元连接采样。模拟器读取 DTB 连接表时还需要匹配的格式和模型实现，不能仅凭文件扩展名判断兼容性。

## 既有生成器的计算流程

已检查的项目适配脚本为 `generate_brain407_tables.py`。它依赖外部 `LGlab_DBS` 的连接表生成模块，调用其中的参考模型和 `generation.make_block`。这些代码未捆绑在公开仓库中。

### 1. 读取并分离矩阵含义

输入必须为无表头、逗号分隔的268 × 268数值矩阵。既有生成器检查元素有限、非负，并要求全部对角灰质权重为正。

令输入为 `M`，提取 `g = diag(M)`，复制得到结构矩阵 `W` 后将 `W` 的对角置零。`g` 用于神经元规模分配，`W` 用于连接概率计算。不要将整张 `M` 直接归一化为同一种连接权重。

来源说明记录非对角流线计数小于2的连接已置零。读取已处理矩阵时应保留其数值和节点顺序，不能默默补边、重排或添加新的阈值处理。

### 2. 按行归一化结构权重

对非孤立脑区，使用 `P[i,j] = W[i,j] / sum(W[i,:])`。对行和为零的脑区，保留全零的跨脑区概率行，不进行除零，也不删除该脑区。

这个按行归一化步骤是既有生成器的采样约定。它不赋予流线计数新的生理方向性，也不意味着可以任意转置或对称化输入。应保留所获矩阵的行列顺序，并与授权节点表对齐。

### 3. 分配兴奋与抑制群体

每个脑区扩展为兴奋 E 和抑制 I 两个神经元群体，顺序为 E 在 I 前，共536个群体。灰质权重先除以其总和，再由参考模型按4:1的 E/I 比例生成群体规模比例。

对群体 `k`，既有分配规则为 `int(max(fraction[k] * requested_scale, minimum[k]))`。E 群体最少200个神经元，I 群体最少50个。该规则同时存在截断取整和数量下限，因此实际总数可以与请求规模不同；应读取生成记录中的 `actual_neurons`。

### 4. 构建连接概率并采样

参考模型将脑区结构概率扩展为 E/I 群体连接概率，使用原生成器的本地、外部和通道规则。对于孤立脑区，不新增跨脑区连接，本地 E/I 采样概率重新归一为0.8/0.2。

2026-10-10 所检查输出的共同配置为：

| 参数 | 既有配置 |
| --- | --- |
| 请求神经元规模 | 2,000,000 |
| 脑区数 / 群体数 | 268 / 536 |
| 输出计算块数 | 2 |
| 入度参数 | 100 |
| 连接权重类型 | `uint8` |
| 随机性记录 | 每次输出保存其种子；并行执行方式也属于复现环境 |

这些参数描述既有生成配置，不是所有研究问题的默认建模选择。完整采样实现和依赖版本应由实际使用的外部代码确定，不能仅凭上述参数重建整个模型。

### 5. 保留索引并验证输出

生成器保留268个脑区的顺序，并记录脑区、E/I 群体、神经元及计算块之间的关联。原节点表中未知的 `is_cortex` 属性在既有输出中编码为 `-1`，不因此删除脑区或推断其解剖属性。

既有 NPZ 格式中的源 block 编号采用相对于接收 block 的编码。它不是普通脑区编号，解析时必须结合匹配的块边界和源神经元下标。

既有验证器检查数组形状和类型、有限值、神经元与群体编号、通道参数、入度，以及源 block 与源神经元下标成对的合法范围。验证完成后才把 manifest 状态更新为 `validated`。源矩阵、参考代码、参数、种子和验证结果应与输出一起保存。

## 在获得授权环境后运行

完整生成需要项目适配脚本、外部参考模型及连接表生成模块、NumPy、mpi4py、sparse 和可用的 MPI 运行环境。精确复现还应记录整个代码版本、依赖版本与并行配置，不能只保留单个参考文件的哈希。

既有项目适配脚本提供 `--input`、`--output`、`--scale`、`--seed`、`--nodes-metadata` 和 `--preflight` 参数。仅收到八个数据目录时，不能假设数据根目录同时包含节点表；应把授权取得的节点表路径显式传入 `--nodes-metadata`。

以下为运行顺序，实际命令与环境启动方式由外部代码维护者提供：

1. 取得匹配的矩阵、节点表、来源清单及生成器，核对输入文件完整性与矩阵适用性。
2. 为本次运行选择新的输出目录，记录规模、随机种子、代码版本和节点表版本。
3. 使用同一输入及参数执行 `--preflight`，检查形状、非负与有限值、灰质权重和预计模型规模。
4. 在匹配的 MPI 环境中执行生成，再运行该版本对应的输出验证器。
5. 检查实际神经元数量、索引关联和验证状态，保存完整运行记录后再交给兼容的模拟器。

公开仓库未提供上述外部程序，因此这部分是流程教程，不能作为可独立运行的 DTB 安装包。仅完成脑区边表导出不表示神经元连接表已经生成。

## 如何解释历史验证状态

2026-10-10 检查的8份既有 manifest 均记录 `validated`，当次复核了预期文件存在性及 block NPZ 字节大小与记录的一致性。该检查没有重新验证全部 NPZ 数组内容或计算其全文件哈希。2026-10-11 的公开文档整理没有追加数据验证。

生成验证状态与原矩阵的 `candidate_pending_human_review` 等质量状态分别记录。连接表生成成功不等于源影像人工审核通过，也不证明所有模拟器版本均能直接加载。相关字段解释见 [metadata 说明](metadata.md)，文档来源见[来源与版本](provenance.md)。
